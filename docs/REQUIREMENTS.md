# 要件定義 — Tetsu English

オーナー（yuuto-moriya）が最初に出した要件と、開発中に決めた事項をまとめたものです。
**機能の追加・変更や UI 改善の前に必ず読み、ここに書かれた方針から外れる場合はオーナーに確認してください。**
決定事項が変わったら、このファイルも更新します。

## 1. 目的

英語の **学習** と **翻訳** をひとつで扱える統合アプリ。
初学者〜上級者が、日常で必要な英語の学びから実務での実践まで、段階的に身につけられることを目指す。
主な利用者は、日本の大手企業で鉄道保線・設備管理（EAM）に関わる人。

## 2. 機能要件（オーナーの指示）

| # | 要件 | 実装の状況 |
|---|---|---|
| R1 | ビジネス英語。**鉄道保線用語** は EU/EN 規格・JIS・EU 規格に照らして正確に | 保線・EAM 用語 422語（TSI INF 付録S、EN 13848 ほか、JIS E 1001 を参考）。出典タグ付き。`docs/RAIL_GLOSSARY.md` |
| R2 | 単語は **3,000語以上**、レベル別 | 3,824語（一般 2,847／ビジネス 555／保線 422）、6段階（入門A1〜専門） |
| R3 | 初心者〜上級者まで、**実践的なリスニングとスピーキング** | リスニングクイズ、ディクテーション、シャドーイング5段階、発音評価（Azure Speech） |
| R4 | 解説には **実際に使われる例文** を付ける | 全語に英日例文 |
| R5 | **発音記号（IPA）** を付ける | 全語に米音 IPA。保線用語は英音 IPA も |
| R6 | 基本的に **すべてに音声** を付ける | 端末の音声合成（Web Speech API）で単語・例文・会話を読み上げ。通常／ゆっくり |
| R7 | **翻訳機能は学習とは別** に設ける | 翻訳画面（Azure Translator）。保線用語を検出し英国表記・米国表記・JIS を併記 |
| R8 | **犬のキャラクター** が案内・サポート・励まし。Blender で作成 | コーギーの「テツ」。`scripts/blender/` で作成し、表情別の 2D 画像（8種）に書き出し |
| R9 | **シチュエーション別学習**：日常会話とビジネスシーンを分ける | シーン 30本（日常10／ビジネス10／保線現場10）、ロールプレイ付き |
| R10 | **モダンで最先端** の言語・フレームワーク | React 19, TypeScript 7, Vite 8, Tailwind CSS v4, React Router 8 |
| R11 | **レスポンシブ**（主に iPhone） | iPhone 幅（390px）を基準に設計。ホーム画面に追加する PWA |
| R12 | **ダークモード** | ライト／ダーク／端末に合わせる |
| R13 | 効率よく習得・定着できるよう、**論文・研究を調べてシステムに反映** | 下の「4. 学習設計」。根拠の一覧は `docs/RESEARCH.md` とアプリ内「学習法の根拠」 |

## 3. 決定事項

| 項目 | 決定 | 理由・補足 |
|---|---|---|
| アプリ形態 | PWA（React 19 + Vite） | iPhone のホーム画面に追加して使う。ストア申請不要 |
| 翻訳 API | Azure AI Translator | 無料枠あり（DeepL API Free は新規受付終了） |
| 音声 | 読み上げは端末の TTS、発音評価・音声入力は Azure AI Speech | 読み上げは無料・オフラインで動く |
| キャラクター | Blender の 3D モデル → 表情別 2D 画像 | 犬種はコーギー |
| 英語の基準 | **米国英語** が基本。保線用語は **英国（EN）・米国表記を併記** | |
| 学習データの保存 | **端末内のみ**（IndexedDB）。アカウント・サーバー保存なし | 機種変更はバックアップ／復元で対応 |
| ホスティング | **Vercel**（GitHub 連携。`main` への push で本番、`staging` への push で検証環境に自動デプロイ） | 2026-10 に Cloudflare Pages から変更 |
| ブランチ運用 | `main` = 本番、`staging` = 検証。修正は `staging` から切ったブランチで行い、`staging` へ PR → 確認後 `staging` から `main` へ PR | 環境を `main` と `staging` で切り分ける |
| API | Vercel Functions（`api/`）。処理本体は `server/` | API キーはサーバーの環境変数にだけ置く |
| リポジトリ | GitHub `yuuto-moriya/English_learning_app` | 成果物はすべてここで管理 |

## 4. 学習設計（研究に基づく）

| 手法 | アプリでの実装 |
|---|---|
| 分散学習・間隔反復 | FSRS（ts-fsrs）で復習日を決める |
| 想起練習（テスト効果） | 新出語は提示 → すぐ選択式で想起。正解を見る前に答える |
| セッション内の再テスト | 間違えた語は同じセッション内で再出題 |
| 難易度の段階づけ | 選択 → リスニング → フリップ → スペル／穴埋め |
| インターリーブ | カテゴリ・出題形式を混ぜる |
| 産出効果 | 例文を声に出して読むよう促す |
| シャドーイング | 聞く → 見ながら → 重ねる → 見ずに → 録音して比べる の5段階 |
| 発音フィードバック | Azure の発音評価（文・単語・音素のスコア） |
| タスク型学習（TBLT） | シーン別ロールプレイ |
| 教育エージェント・過程への称賛 | テツが努力や継続をほめる（結果だけでなく過程を） |
| 習慣化 | 連続日数、1日の目標 |

## 5. 守ること（変更時の制約）

- 表示文言は **日本語**。英語は学習対象としてのみ表示する
- 学習データ（`src/data/vocab/*.json`）は手で編集しない。`data-src/` を直して `npm run data:build`
- 保線用語の定義は規格本文の転載をしない（要約・意訳）。出典タグを付ける
- API キーやトークンをコード・`vercel.json`・リポジトリに書かない
- 学習データを端末の外へ送らない（翻訳・発音評価で送るのは入力文と録音だけ）
- iPhone の Safari と、ホーム画面に追加した状態（standalone）の両方で動くこと
- 入力欄の文字は 16px 以上（iOS の自動ズーム防止）
