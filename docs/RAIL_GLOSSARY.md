# 保線・設備管理用語集（Rail Glossary）

Eliza Patina の「鉄道・保線」カテゴリ（レベル「専門」を中心に約420語、2026年10月時点）は、
欧州の規格・法令の用語体系と JIS の線路用語を突き合わせて、本プロジェクトで独自に編集した用語集です。
単語学習に加えて、翻訳画面の **専門用語検出**（英国表記／米国表記／JIS日本語を並べて表示）にも使われます。

- 元データ: `data-src/rail/*.txt`（パイプ区切りのテキスト、このファイルを編集する）
- ビルド成果物: `src/data/vocab/rail.json`（`npm run data:build` で生成。直接編集しない）
- 表示: 単語帳 → 保線、単語詳細（英国/米国表記・英米のIPA・解説・出典タグ）、翻訳画面の用語チェック

## 1. 構成

| ファイル | サブカテゴリ | 主な内容 |
|---|---|---|
| `general.txt` | 線路一般・線形 | permanent way, track, line, 曲線・カント・勾配 |
| `structure.txt` | 軌道構造・材料 | 軌きょう、バラスト／スラブ軌道、まくらぎ、締結装置 |
| `rail.txt` | レール・継目・溶接 | レール各部、継目、ロングレール、各種溶接 |
| `snc.txt` | 分岐器 | S&C、turnout / points / switch、クロッシング |
| `geometry.txt` | 軌道狂い・検測 | 軌間・水準・高低・通り・平面性、検測車 |
| `defect.txt` | 損傷・劣化 | レール損傷（UIC 712）、RCF、探傷 |
| `work.txt` | 保線作業・機械 | つき固め、マルタイ、レール削正、更新工事 |
| `safety.txt` | 安全・運転取扱い | 線路閉鎖、防護、列車見張員、徐行 |
| `civil.txt` | 土木・構造物 | 路盤、路床、排水、橋りょう、トンネル |

サブカテゴリの表示名は `src/lib/types.ts` の `RAIL_SUBS` で定義しています。

## 2. 編集方針と出典

### 見出し語（英語）
- **英国表記・欧州規格の用語を見出し語** にしています（例: *permanent way*, *sleeper*, *possession*）。
  EU の相互運用性技術仕様 **TSI INF**（Commission Regulation (EU) No 1299/2014、EU では 2023 年に改正）の
  **Appendix S（Glossary）** の定義語と、欧州規格（EN）の用語体系を基準にしました。
- **米国表記を併記** しています（例: sleeper → *tie*, possession → *track outage*）。米国の鉄道規則・業界標準で
  一般的な語を採用し、英国と同じ場合は同じ語を書いています。
- 発音記号は **英音（UK）と米音（US）** の両方を付けています。

### 参照した規格・資料（用語体系の参照のみ。本文は転載していません）

| 分野 | 参照した規格・資料 |

| 軌道形状・軌道狂い | EN 13848 シリーズ（-1, -2, -4, -5, -6） |
| 分岐器 | EN 13232 シリーズ |

### 日本語訳
- **JIS E 1001 の用語を優先** し、現場での通称を併記しています（例: マルチプルタイタンパ（マルタイ））。
- 英語圏に対応する概念がない日本独自の工法などは「日本の実務」タグを付けています。

### 解説・例文
- 解説（`note`）は、上記の規格・法令の定義を **参考に要約・言い換えて独自に執筆** したもので、規格の正式な定義文ではありません。
- 英国と米国で意味や範囲が異なる語（例: *formation* / *subgrade*）は解説で注意を促しています。
- 例文は、保線現場・点検記録・規格の議論などを想定したオリジナルの文です。

## 3. 出典タグ（`refs`）の意味

単語詳細画面に表示されるタグです。1語に複数付けられます（`;` 区切り）。規格番号のタグは編集に応じて増えることがあります。

| タグ | 意味 |
|---|---|
| `一般用語` | 英語圏の鉄道・土木分野で広く使われる一般的な用語。特定の規格の定義語ではない |
| `英国実務` | 英国の鉄道現場や社内規程で慣用的に使われる表現（規格の定義語ではない）。米国では別の語を使うことが多い |
| `日本の実務` | 日本の保線現場で使われる用語・工法。英語は説明的な訳になる |
| `SAP EAM` | SAP の設備保全（PM / EAM）で使われる用語（機能場所、保全オーダ、保全通知、測定ポイントなど） |
| `JIS E 1001` | 日本語訳語が JIS の線路用語に基づく |
| `TSI INF App.S` | TSI INF Appendix S（Glossary）の定義語 |
| `Directive (EU) 2016/797` | EU の鉄道相互運用性指令の用語（サブシステム、適合性評価など） |
| `EN xxxxx` | その欧州規格の用語体系・定義に沿った語（例: `EN 13848-1`, `EN 13306`） |
| `UIC 712` | UIC のレール損傷分類（UIC Code 712 / IRS 70712）に含まれる語 |
| `ISO 55000` | アセットマネジメントの国際規格の用語 |
| `CSM-RA` | EU の共通安全手法（リスク評価）の用語 |
| `AREMA` | 米国の保線・鉄道技術の協会（AREMA）とそのマニュアルに関する語 |

## 4. 著作権について

- EN・UIC・ISO・JIS などの規格は著作物です。**規格本文（定義文・表・図）はこの用語集に転載していません。**
  規格番号・規格名は、用語の出典・参照先を示すためにのみ記載しています。
- 解説はすべて、学習者向けに要約・言い換えた独自の文章です。
- TSI INF は EU 法令です。EU 法令の再利用は Commission Decision 2011/833/EU で認められています。
  参照した legislation.gov.uk のページ（英国の旧「retained EU law」版。英国では 2020 年 12 月 31 日に失効）は
  Open Government Licence v3.0 で提供されています。最新の EU 版は EUR-Lex の統合版を確認してください。
- **実務で使う場合は、必ず最新の正式な規格・法令・社内規程を確認してください。** 規格の改訂により、
  用語や定義が変わっている可能性があります。

データ全体のライセンスは [DATA_LICENSE.md](../DATA_LICENSE.md) を参照してください。

## 5. 用語の追加・修正

### 書式（1行1語・10列）

```
en|us|ja|lv|ipa_uk|ipa_us|refs|note|example_en|example_ja
```

| # | 列 | 内容 | 例 |
|---|---|---|---|
| 1 | `en` | 見出し語（英国表記・EN/TSI の用語） | `possession` |
| 2 | `us` | 米国表記。英国と同じなら同じ語（空でも可） | `track outage` |
| 3 | `ja` | 和訳。複数は `；` で区切る | `線路閉鎖` |
| 4 | `lv` | レベル `4`（中上級）/ `5`（上級）/ `6`（専門） | `6` |
| 5 | `ipa_uk` | 英音IPA（`/ /` は付けない） | `pəˈzeʃn` |
| 6 | `ipa_us` | 米音IPA。**空なら自動生成**（ipa-dict。複合語は語ごとに合成） | `ˈtræk ˌaʊtɪdʒ` |
| 7 | `refs` | 出典タグ。複数は `;` で区切る | `JIS E 1001;英国実務` |
| 8 | `note` | 解説（言い換え・要約で書く。規格本文をコピーしない） | `保守のため…` |
| 9 | `example_en` | 例文（英）。**対象語を `*アスタリスク*` で囲む** | `We have a six-hour *possession* on Sunday night.` |
| 10 | `example_ja` | 例文（和） | `日曜の夜に6時間の線路閉鎖がある。` |

例（`safety.txt`）:

```
possession|track outage|線路閉鎖|6|pəˈzeʃn|ˈtræk ˌaʊtɪdʒ|JIS E 1001;英国実務|保守のため一定区間に列車を進入させない取扱い。英国ではpossession（線路の占有）、米国ではtrack outage / track and time などと言う。|We have a six-hour *possession* on Sunday night.|日曜の夜に6時間の線路閉鎖がある。
```

### ルール

- `#` で始まる行はコメント、空行は無視されます。各ファイルの1行目はサブカテゴリ名のコメントです。
- フィールド内で `|` は使えません。**列数が10でない行は警告を出してスキップ** されます。
- 例文の対象語は `*...*` で囲みます。囲んでいない場合は、ビルド時に見出し語 → 米国表記 → 見出し語の先頭単語の順で自動的に探して囲みます（見つからなければ警告）。
  例文穴埋め問題はこの印を使うので、活用形（*faults* など）もそのまま囲んでください。
- 和訳に JIS 用語を別に示したい場合は `訳語〔JIS用語〕` と書くと、〔 〕内が JIS 用語として別に表示されます（任意）。
- `ja` は `；`・`、`・`・`・`/`・括弧で区切られ、2文字以上の部分が翻訳画面の日本語用語検出に使われます。
  英語の検出は `en` と `us`（3文字以上、複数形の `s` も一致）です。
- ID は `r-` + 見出し語のスラッグ（例: `r-track-gauge`）です。**既存語の `en` を変えると ID が変わり、その語の学習履歴が引き継がれません。**
  綴りの修正以外では、`en` の変更は避けてください。同じ ID になる語は重複として警告され、後の行がスキップされます。

### 手順

1. 該当する `data-src/rail/<サブカテゴリ>.txt` を編集する
   （新しいファイルを追加する場合は `scripts/build_vocab.py` の `RAIL_FILES` と `src/lib/types.ts` の `RAIL_SUBS` にも追加）
2. 米音IPAの辞書を用意する（初回のみ。手順は README の「データパイプライン」を参照）
3. `npm run data:build` を実行し、出力の `[WARN]`（列数・重複・例文の対象語）と
   `[INFO] 米音IPAなし`（`ipa_us` を手入力するか、`build_vocab.py` の `OVERRIDE_US` に追加）を確認する
4. `npm test` でデータの整合性テストを通す
5. `npm run dev` で、単語帳 → 保線、単語詳細、翻訳画面の用語チェックで表示を確認する
6. `data-src/rail/*.txt` と `src/data/vocab/rail.json` の両方をコミットする
